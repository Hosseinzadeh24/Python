# مشاور کریپتو با والکس (Wallex) — ویندوز ۱۱ و VS Code

این برنامه روی **صرافی والکس** کار می‌کند: قیمت‌ها و کندل‌های تاریخی را از والکس می‌گیرد، با مدل یادگیری ماشین تحلیل می‌کند، و در صورت انتخاب شما می‌تواند **خرید و فروش خودکار** انجام دهد. دو حالت آزمایشی و کاملاً مطمئن هم دارد که قبل از استفاده با پول واقعی بتوانید رفتار آن را ببینید.

> **هشدار مهم**
> - معامله رمزارز ریسک بالا دارد و ممکن است **کل سرمایه‌ای را که اختصاص می‌دهید از دست بدهید**.
> - «احتمال» و «سود مورد انتظار» در برنامه برآورد مدل است، **تضمین نیست**. این یک ابزار کمکی است، نه توصیه سرمایه‌گذاری.
> - حد ضرر (Stop-loss) فقط وقتی کار می‌کند که **برنامه باز و کامپیوتر روشن** باشد. اگر کامپیوتر خاموش، خواب یا قطع اینترنت باشد، فروش خودکار انجام نمی‌شود. (حد ضرری که روی خود صرافی گذاشته شود در این نسخه استفاده نشده است.)
> - این نسخه **هنوز با API واقعی والکس تست نشده** است (توضیح در بخش «وضعیت تست»). پیش از حالت واقعی حتماً مراحل بخش «ترتیب پیشنهادی استفاده» را طی کنید.

## ۱. امکانات

| بخش | توضیح |
|---|---|
| کلید API | کادر رمزشده برای وارد کردن کلید والکس. کلید در **Windows Credential Manager** ذخیره می‌شود و هرگز در فایل پروژه یا لاگ چاپ نمی‌شود. |
| داده لحظه‌ای | قیمت خرید (bid)، فروش (ask)، آخرین قیمت و تغییر ۲۴ ساعته هر چند ثانیه از والکس (`/v1/markets`). |
| داده تاریخی | کندل‌های یک‌ساعته از `/v1/udf/history` با صفحه‌بندی، فقط کندل‌های بسته‌شده (کندل در حال تشکیل حذف می‌شود). |
| بازارهای USDT و تومانی | بازارهای USDT (BTCUSDT، ETHUSDT، SOLUSDT) و تومانی (مثل BTCTMN) پشتیبانی می‌شوند. سرمایه هر ارز جداگانه است و سود، زیان و سقف‌ها بین دو ارز مخلوط نمی‌شوند. |
| حد ضرر (Max loss %) | شما درصد را وارد می‌کنید؛ **حداکثر ۱۵٪** است و برنامه بالاتر از آن را قبول نمی‌کند. |
| حد سود (Min profit %) | درصد سود هدف. باید بیشتر از هزینه رفت‌وبرگشت (حدود ۰٫۵٪) باشد. |
| خرید و فروش | سفارش **حدی (LIMIT)** روی والکس. حد سود به‌صورت سفارش فروش روی خود صرافی گذاشته می‌شود. |
| هشدار فرصت | وقتی مدل احتمال صعود ≥ ۷۰٪ و سود خالص مورد انتظار ≥ ۳٪ باشد، هشدار «فرصت سرمایه‌گذاری» می‌دهد تا اگر خواستید سرمایه بیشتری بگذارید. |
| دکمه اضطراری | **KILL SWITCH**: سفارش‌های باز این برنامه را لغو می‌کند و خرید جدید را متوقف می‌کند. با تیک «also sell all positions» همه پوزیشن‌ها را هم می‌فروشد. |

## ۲. نصب (یک‌بار)

۱. **Python 3.12** را از python.org نصب کنید و گزینه **Add python.exe to PATH** را تیک بزنید. (Tkinter همراه نسخه رسمی ویندوز است.)
۲. پوشه `crypto_advisor` را در VS Code باز کنید.
۳. فایل **`setup_windows.bat`** را اجرا کنید. کتابخانه‌ها (از جمله `keyring`) نصب می‌شوند.

---

## ۳. کلید API والکس

۱. در والکس وارد **wallex.ir/app/my-account/api-management** شوید و کلید بسازید.
۲. **پیشنهاد امنیتی:** کلید را **بدون** دسترسی برداشت (Withdrawal) بسازید. فقط دسترسی خواندن و معامله کافی است.
۳. **پیشنهاد امنیتی:** اگر امکانش هست، **IP کامپیوتر خود را در لیست سفید (IP whitelist)** قرار دهید.
۴. توجه: طبق مستندات والکس، هر کلید حداکثر ۹۰ روز اعتبار دارد و تمدید نمی‌شود؛ باید کلید جدید بسازید.
۵. کلید را در کادر **Wallex API key** در پنجره برنامه بچسبانید و دکمه **Save key** را بزنید. سپس **Test key** را بزنید تا مطمئن شوید کار می‌کند (این تست فقط خواندن است و سفارشی ثبت نمی‌کند).

روش جایگزین: متغیر محیطی `WALLEX_API_KEY` را تنظیم کنید (برای اجرای بدون پنجره).

## ۵. حالت‌های کار

در پنجره یکی از سه حالت را انتخاب کنید:

1. **Suggest only (فقط پیشنهاد):** هیچ سفارشی ثبت نمی‌شود. فقط تحلیل و هشدار.
2. **Dry run (آزمایشی):** همه منطق خرید/فروش اجرا می‌شود، اما سفارش‌ها **شبیه‌سازی** می‌شوند و با قیمت‌های واقعی والکس پر می‌شوند. **پول واقعی خرج نمی‌شود.** نتایج در `output/trader_dry_run.json` ذخیره می‌شود.
3. **LIVE (واقعی):** سفارش واقعی روی والکس. برای شروع، برنامه از شما می‌خواهد عبارت **`I ACCEPT RISK`** را دقیقاً تایپ کنید. بدون آن شروع نمی‌شود. کلید API هم لازم است.

## ۶. تنظیمات ریسک (داخل پنجره یا `config.json`)

| تنظیم | پیش‌فرض | معنی |
|---|---|---|
| Max loss % | ۵ | اگر قیمت این‌قدر زیر قیمت خرید برود، فروش خودکار (حد ضرر). حداکثر ۱۵ |
| Min profit % | ۵ | قیمت هدف فروش به‌صورت سفارش حدی روی والکس |
| Capital (USDT) | ۱۰۰۰ | بیشترین سرمایه‌ای که برنامه برای بازارهای USDT استفاده می‌کند |
| Capital (TMN) | ۰ | بودجه تومانی برای بازارهای تومانی. ۰ یعنی بازارهای تومانی خاموش‌اند |
| min_order_tmn | ۵۰۰٬۰۰۰ | حداقل ارزش هر سفارش به تومان |
| Max invested % | ۶۰ | حداکثر درصدی از سرمایه که همزمان در بازار است |
| max_position_frac | ۰٫۲۵ | حداکثر سهم هر ارز از سرمایه |
| max_daily_loss_frac | ۰٫۰۳ | اگر ضرر امروز از ۳٪ سرمایه گذشت، خرید جدید تا فردا متوقف می‌شود |
| max_drawdown_kill | ۰٫۱۵ | اگر ضرر کل از ۱۵٪ گذشت، معامله متوقف می‌شود و **فقط با دکمه Resume دستی** باز می‌شود |
| max_hold_hours | ۷۲ | پوزیشن بعد از این مدت بسته می‌شود |
| fee_rate | ۰٫۰۰۲ | کارمزد فرض‌شده (۰٫۲٪). کارمزد واقعی را در حساب والکس بررسی کنید |

**نکته:** حد ضرر و حد سود بر اساس درصد **شما** تنظیم می‌شوند (نه ATR). برنامه در تحلیل هم همین درصدها را برای برآورد سود و اندازه پوزیشن به‌کار می‌برد.

## ۷. منطق معامله

- **خرید:** وقتی مدل احتمال صعود ≥ ۶۰٪ بدهد و سود خالص مورد انتظار مثبت باشد، یک سفارش حدی خرید کمی بالاتر از قیمت فروش (ask) گذاشته می‌شود تا سریع پر شود.
- **حد سود:** بعد از پرشدن خرید، یک سفارش فروش حدی روی **خود والکس** در قیمت `خرید × (۱ + حد سود)` گذاشته می‌شود.
- **حد ضرر:** برنامه هر چند ثانیه قیمت را چک می‌کند. اگر قیمت به `خرید × (1 − حد ضرر)` برسد، سفارش‌های فروش قبلی لغو و فروش خروجی گذاشته می‌شود.
- **خروج بر اساس مدل:** اگر مدل سیگنال فروش بدهد، پوزیشن بسته می‌شود.
- **فقط سفارش‌های همین برنامه** لغو می‌شوند؛ سفارش‌های دستی شما در والکس دست‌نخورده می‌مانند. (شناسه سفارش‌های برنامه با `ADV` شروع می‌شود.)

## ۸. فایل‌های خروجی (پوشه `output/`)

- `trader_dry_run.json` / `trader_live.json`: پوزیشن‌های باز، معاملات بسته‌شده، سود و زیان امروز و کل.
- `sim_dry_run.json`: موجودی و سفارش‌های شبیه‌سازی.
- `KILL_SWITCH`: فایل پرچم توقف. تا وقتی وجود دارد خرید جدید انجام نمی‌شود. با Resume حذف می‌شود.
- `alerts.jsonl`: تاریخچه هشدارها. `suggestions_history.csv`: تاریخچه پیشنهادها. `latest.txt`: آخرین خروجی.
- `errors.log`: خطاهای غیرمنتظره.

## ۹. ترتیب پیشنهادی استفاده (مهم)

1. **Suggest only** را چند روز اجرا کنید و پیشنهادها و هشدارها را ببینید.
2. **Dry run** را حداقل چند هفته اجرا کنید. ببینید سود/ضرر شبیه‌سازی‌شده چه بوده و حد ضرر درست کار می‌کند.
3. فقط اگر راضی بودید، **LIVE** را با **مبلغ کم** (مثلاً ۲۰ تا ۵۰ دلار) شروع کنید. اولین سفارش‌ها را در سایت والکس دقیق بررسی کنید: قیمت، کارمزد، و اینکه حد سود واقعاً روی صرافی ثبت شده باشد.
4. کامپیوتر را **روشن و بیدار** نگه دارید (تنظیمات Power ویندوز را روی «Never sleep» بگذارید). برای اطمینان بیشتر، از یک کامپیوتر یا VPS همیشه‌روشن استفاده کنید.
5. هر وقت ضرر زیاد دیدید یا شک داشتید: **KILL SWITCH** یا `run_kill_switch.bat`.

## ۱۰. محدودیت‌های فعلی (صادقانه)

- **تست با API واقعی والکس انجام نشده.** محیط توسعه به `api.wallex.ir` دسترسی نداشت. همه تست‌ها با پاسخ‌های ساختگی طبق مستندات والکس و شبیه‌ساز انجام شد. ممکن است در اولین اجرا خطای فرمت یا محدودیت‌های ناشناخته ببینید؛ برای همین مرحله ۱ و ۲ را جدی بگیرید.
- **بازارهای تومانی** (مثل BTCTMN) فقط با مقدار «Capital (TMN)» بزرگ‌تر از صفر فعال می‌شوند. فرمت قیمت و حجم آن‌ها (تعداد اعشار `tickSize` و `stepSize`) طبق مستندات والکس خوانده می‌شود، اما روی API واقعی هنوز تست نشده است.
- **تأیید دستی هر سفارش** وجود ندارد. فقط یک‌بار در شروع حالت live عبارت `I ACCEPT RISK` پرسیده می‌شود و بعد سفارش‌ها خودکار ثبت می‌شوند.
- **Stop-loss نرم‌افزاری است** (توسط برنامه، نه سرور صرافی؛ این تصمیم عمدی است و سفارش STOP روی سرور استفاده نمی‌شود). اگر برنامه بسته یا قطع شود، حد ضرر اجرا نمی‌شود. حد سود روی خود صرافی هم هست، اما فقط اگر سفارش‌ها پر شده باشند.
- **وب‌سوکت** (داده لحظه‌ای سریع‌تر) در این نسخه نیست؛ داده هر ۱۰ ثانیه با REST گرفته می‌شود.
- **کارمزد و نحوه کسر آن** (از ارز خرید یا از تتر) طبق مستندات روشن نیست؛ برنامه کارمزد ۰٫۲٪ را فرض می‌کند.
- **Taker buy/sell** در داده والکس نیست؛ مدل بدون این ویژگی‌ها آموزش می‌بیند.
- **Android:** این نسخه برای ویندوز است. نسخه APK در پوشه `mobile/` پروژه اصلی جداست.

## ۱۱. وضعیت تست‌ها

- `python -m pytest tests` — ۵۲ آزمون، شامل: بازارهای تومانی و سود/زیان جدا از تتر، سقف‌های ریسک جدا برای هر ارز، فرمت و احراز هویت HTTP با سرور ساختگی، قفل ۱۵٪، کنترل حد سود نسبت به کارمزد، حد ضرر و حد سود، حد روزانه، کیل سوییچ (فقط سفارش‌های خودمان)، ادامه پس از ری‌استارت، کمبود موجودی، سقف سرمایه، فرمت درخواست‌های والکس، و تحلیل کامل روی داده ساختگی.
- **تست نشده روی ویندوز:** پنجره Tkinter و `.bat` ها (در محیط توسعه Tkinter نصب نبود).
- **تست نشده با والکس زنده:** همه تماس‌ها با API واقعی.

## ۱۲. خطاها و راه‌حل

- **Live trading was not started:** عبارت `I ACCEPT RISK` را دقیق تایپ نکرده‌اید.
- **No API key:** کلید را ذخیره کنید یا `WALLEX_API_KEY` را تنظیم کنید.
- **Key test failed:** کلید را بررسی کنید، IP سفید شده باشد، یا مدت اعتبار کلید تمام نشده باشد.
- **Could not reach Wallex:** اینترنت، فیلترینگ، یا خاموش بودن سرویس والکس. برنامه چند بار دیگر تلاش می‌کند.
- **HALTED:** توقف خودکار به دلیل ضرر روزانه یا کل. با Resume (فقط برای توقف دستی یا ضرر کل) ادامه دهید.
- **فایل `config.json` را دستی ویرایش کردید:** مقادیر نامعتبر (مثلاً `max_loss_pct` بیشتر از ۱۵) باعث توقف برنامه با پیام خطا می‌شود.
